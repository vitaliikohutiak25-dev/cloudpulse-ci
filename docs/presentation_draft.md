# Чернетка структури презентації фінального демо (5-7 хвилин)

## Слайд 1. Титульний
- Назва проєкту: CloudPulse Telemetry API
- Виконавець: Віталій Когутяк (vitaliikohutiak25-dev)
- Дисципліна: Інженерія програмного забезпечення

## Слайд 2. Проблема та мета проєкту
- Проблема: відсутність стандартизованого, ізольованого та легкоатлетного сервісу моніторингу стану вузлів у кластері.
- Мета: розробка надійного контейнеризованого мікросервісу з повноцінним CI/CD циклом та аудитом безпеки.

## Слайд 3. Функціональні та нефункціональні вимоги
- Функціональні: швидкий health check через REST API, конфігурація через ENV без перекомпіляції.
- Нефункціональні: час відповіді < 50 мс, розмір базового образу < 150 МБ, підтримка стандартів OWASP.

## Слайд 4. Архітектура та стек технологій
- Стек: Python 3.11, Flask 3.1.3, Redis 7.2, Docker Compose, GitHub Actions.
- Схема C4: зв'язок клієнта, контейнера API та контейнера кешу у віртуальній мережі pulse_net.

## Слайд 5. Демонстрація роботи (Live Demo / Скріншоти)
- Демонстрація відповіді API у форматі JSON (`status: ONLINE`).
- Запуск мультиконтейнерного стеку однією командою: `docker compose up -d`.

## Слайд 6. Забезпечення якості та тестування
- Модульні тести: 100% проходження автотестів на базі Pytest.
- Статичний аналіз: Pylint рейтинг 9.29/10, SAST сканування утилітою Bandit.
- SCA-аудит: перевірка залежностей утилітою pip-audit.

## Слайд 7. CI/CD автоматизація
- GitHub Actions workflow: паралельна матриця на Python 3.10 і 3.11.
- Автоматична перевірка коду лінтером і тестами при кожному push.
- Генерація релізного ZIP-артефакту.

## Слайд 8. Висновки та подальший розвиток
- Результати: створено повністю відтворюваний, протестований та задокументований мікросервіс.
- Майбутнє: додавання авторизації через токени JWT та дашборду метрик у Grafana.
